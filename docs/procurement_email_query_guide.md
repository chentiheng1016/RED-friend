# 採購信查詢使用說明（給業務 / 大王）

> 工具：`read_dept_email_timeline`（`agent_core/lake_dept_timeline.py`，SAFE tier，免 +確認）
> 資料源：內部郵件 lake `var/data/data_lake_internal/emails.parquet`
> 盤點日期：2026-06-25（live 數據）

## 一句話

採購十年的信（**2,537 封 primary thread、2016–2026、最新到 6/24**）已經是**可查的狀態時間軸**。
業務不用學任何指令，**直接用講的問小紅**，小紅會自動翻採購信、按日期新→舊整理回來，每筆帶日期＋主旨＋摘要。

---

## 一、業務這樣問就行（複製即用）

| 想知道什麼 | 跟小紅這樣講 | 小紅會回 |
|---|---|---|
| 最近採購在忙什麼 | 「採購最近的信整理給我」 | 近期全部採購 thread 時間軸 |
| 某張單催到哪 | 「採購 JF0P26060008 進度」 | 該單號相關往來（交期／取消／改規） |
| 某客戶的料況 | 「採購 Decathlon 最近狀況」 | 該客戶用料／出貨／預付通知 |
| 交期有沒有延 | 「採購這個月交期的信」 | 近 30 天交期確認／延誤 |
| 對帳付款卡住沒 | 「採購跟廠商對帳的狀況」 | 對帳單／貨款／匯款往來 |
| 某材料／廠商 | 「採購 NASTROTEX 的信」 | 該廠商／材料 thread |

實測例（2026-06-22，查 Decathlon）：
- 「27 捲貨櫃已寄送，預計 6/29 到福群工廠」
- 「福群收到 NASTROTEX LOT 217-2026 預付款通知，共 EUR$5400，大貨預計 7/10 出貨」

→ 這種「**狀態 + 日期 + 金額**」它都抓得到。

## 二、底層對照（技術備查）

```python
read_dept_email_timeline(dept='採購', query='', days=0, limit=20)
```

| 參數 | 說明 |
|---|---|
| `dept` | 部門名。可查：`老闆 / 業務 / 樣品室 / 生產管理 / 採購 / 船務 / 會計 / 倉庫` |
| `query` | 客戶／單號／關鍵字，比對 **主旨＋摘要＋品牌**（大小寫不拘）；留空＝最近全部 |
| `days` | 只看近 N 天；`0`＝不限（預設） |
| `limit` | 回幾筆 thread（預設 20） |

採購信標籤分布（前幾名，verified）：
PO確認 1,136 ／ 交期延誤 481 ／ 付款通知 381 ／ 規格變更 376 ／ 對帳 154 ／ 樣品催貨 140 ／ 價格異議 91 ／ 驗貨 73 ／ 報價・詢價 120。

## 三、分流（別問錯工具，小紅會自己分流）

採購信查的是**往來狀態**（誰催了什麼、交期、對帳）。要**精確數字／單據**時走專用工具：

| 要查 | 用哪支 |
|---|---|
| 樣品進度 | `read_sample_status` |
| 客戶訂單量 | `read_customer_order_pos` |
| 量產進度 | `read_production_progress_sheet` |

---

## 四、兩條一定要記得的限制

1. **只有信件摘要，沒有結構化單據** —— 能回「料催到哪、誰回了什麼」，**答不了**「X 型體下了多少料、缺幾捲」。
   那需要 ERP 的材料 PO ＋ BOM，目前缺（即生產排程專案撞 BOM 牆那塊；料號↔倉庫庫存編號對照未解）。
2. **數量／單價／明細要再開 Drive 夾或業務確認信** —— 小紅每筆結尾都會自動加這句提醒。
